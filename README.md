# ねむりの厳選手帳（テスト版）

ポケモンスリープの食材担当と厳選状況を手入力で管理する、スマートフォン対応の非公式Webアプリです。

## 機能

- 個体の登録・編集、食材3枠、性格の上昇・下降表示、手動の厳選完了
- ひらがな・カタカナの種族検索、レベル枠ごとの金・青・白サブスキル選択
- 食材・きのみ担当の固定比較カード（性格枠、レアリティ別サブスキル、最終進化時の表示名）
- 現在／50／60／70／80の表示切り替え（現在レベルを下げない）
- 条件を明記した通常おてつだい24時間の食材期待値
- 現在の条件で食材とくい・きのみとくいの最適担当を自動選出（登録・編集・削除・条件変更に連動）
- 白背景のnote風デザイン、全19食材・全18きのみの省スペース一覧と4列の高解像度PNG共有
- 登録個体のまま／最終進化／おまかせで対象ごとの性能を比較（おやすみリボンを反映）
- 選択した料理3食分と各主担当の出力の比較、食材と担当の一覧
- マップの得意きのみと共通担当を表示（ランダム好物は手動選択）
- シェア画像の作成・保存、CSVバックアップの書き出し・CSV／従来のJSONの読み込み

Lv.80は将来の解放表示のみで数値を出しません。計算情報が不足した個体や未対応の特殊種族も推定値を出しません。スクショ読み取りは将来機能です。

## ローカルで起動

Python 3をインストールした環境で、このフォルダーから次を実行します。

```sh
python3 launch.py
```

Macでは `起動.command` を開いても起動できます。ブラウザーで http://127.0.0.1:8765/ を開きます。ビルドやAPIキーは不要です。

## 保存・端末移行

個体情報はアクセス元のブラウザーのlocalStorageに保存し、サーバーへ送信しません。アクセス解析や外部API呼び出しもありません。通常モードで同じURLを再度開けば保存内容を読み込みます。プライベートブラウズ、サイトデータ削除、端末の保存領域整理では消えることがあるため、定期的にバックアップしてください。

「保存・復元」からCSVを書き出し、別端末で読み込みます。従来のJSONバックアップも復元できます。CSVはUTF-8 BOM付きで、個体の全項目と担当・履歴・計算条件を保持します。配列・空欄・未入力を区別するため、値の列にはJSON表記を使います。復元前に形式・内容を検証し、件数の確認後に現在のデータを置き換えます。iPhoneではダウンロードしたCSVをファイルアプリに保存し、復元時にそのファイルを選択してください。ローカル版とPages版、別ブラウザーの間も同じ方法で移行できます。バックアップは個体情報を含むため、GitHubにアップロードしないでください。GitHub Pagesは同じホスト名内の別プロジェクトと保存領域を共有するため、同じアカウントのPagesには信頼できるコードだけを配置してください。

画像は「画像でシェア」から作成し、保存リンク、または画像の長押しで保存します。外部への投稿は自動で行いません。

## 計算・出典・テスト

初期条件はげんき100一定、24時間、所持数が満杯になる前に回収です。本人の補正を反映し、他個体の補助・メインスキル・イベント等は含めません。実際の同時編成で3食作れる保証ではありません。

Neroli’s Labの採用版・個別更新日・出典は「条件とデータ」に記録しています。第三者ライセンスは `licenses/` に同梱しています。

```sh
node tests/core.test.cjs
```

画面表示は `app.js`、計算は `core.js`、共通データは `data.js` です。仕様は `SPEC.md`、開発方針は `AGENTS.md` を参照してください。

## 出典と利用条件

[DATA_SOURCES.md](DATA_SOURCES.md)でカテゴリごとの取得元・採用版・利用条件・未確認項目・変更履歴を管理します。Neroli’s Lab由来部分はApache-2.0ですが、RaenonX追加種族や日本語名称等の別出典に同じ許諾を適用しません。一般公開に必要な条件が全て確認済みとは扱いません。

開発用・テスト用・正式版は別の保存キーを使用します。バックアップを読み込んでも保存先環境は変わりません。既存サイトの保存キーを読み書き・削除しません。

日本語名は表示用で、保存・比較は既存のIDを維持します。PokéAPI基本日本語名の再照合版とBSDライセンスも記録しています。

現在の担当一覧・共有は省スペース型です。未使用のポケモン・きのみゲームPNGは2026-10-07に現行配布から削除し、文字・タイプバッジ・食材絵文字を使用します。開発用が継承した過去履歴には旧画像が残りますが、新しいテスト版の公開履歴へは含めません。登録個体や計算結果には影響しません。

進化は現在／最終進化／リボン込で比較します。条件付き通常24時間の計算で、実際の3食や取得量を保証しません。


食材カードをタップすると、現在の計算条件での日量が多い順に登録個体の候補を確認できます。「担当中」を表示し、候補をタップしても担当は変更しません。保存済みの担当情報は維持します。食材画面はタイプで制限せず、きのみ・マップでは保存済みのタイプ指定を利用できます。きのみの既存の担当選択・「自動に戻す」は維持します。マップでは「きのみ / 食材 / 両方」を切り替えられます。

担当画面は見出し右に「画像でシェア」、その下にLv・進化・キャンチケ・条件を1行で配置します。表示フィルターは文字タブ、並べ替えは基準と昇降をまとめた選択欄です。新規登録はポケモンタブの「＋ 登録」から行います。共有画像の4列レイアウトは変更していません。


## デザインの管理（2026-10-19）

兄弟アプリ [育成リソースノート](https://mokuhibi.github.io/resource-journal-test/) の公開画面と、
[editorial-design.css](https://github.com/mokuhibi/resource-journal-test/blob/85234f572f1a4afb9647fe05ff81cae80460b4dc/editorial-design.css)
を比較し、共通の文字組み・余白・配色に合わせた独自のレイアウトを実装しています。CSS全体の転載ではありません。

- `style.css`：既存機能の基礎レイアウト。`@layer legacy` 内に限定し、過去の詳細度やメディアクエリが現行デザインを上書きしないようにします。
- `note.css`：全6画面の現行デザインを一か所で管理。ヘッダー、28px見出し、20px余白、白背景、#202124の文字、#ECEDEEの区切り線、入力欄、カード、状態色、下部ナビゲーションを定義します。過去の修正を末尾に重ねず、該当する部品のルールを修正してください。
- `share.css`：画像専用の寸法だけを定義。576 CSS px・4列・描画倍率3を維持し、カードの配色・状態は画面用の共通ルールを使用します。通常画面では読み込みません。

食材SVGの対応・透明度12％、食材数/エナジー、性格補正、厳選完了、サブスキルのレアリティ/解放判定は表示データをそのまま使用します。ヘッダーのアイコンは兄弟アプリに合わせて画面上は非表示ですが、ホーム画面/PWA/faviconの画像と設定は維持しています。各画面の計算条件は見出し直下に同じ要素を移動して表示し、値や保存方法を変えません。

動作確認は利用者の保存領域に触れない架空個体・メモリ内保存で行い、320pxと390pxの画面、全タブ、19食材と18きのみの実PNG出力を確認します。計算・マスター・バックアップ処理をデザイン変更に混ぜないでください。
